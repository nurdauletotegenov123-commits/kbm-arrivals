# Учёт прибытия на месторождение — АО «Каражанбасмунай»

Веб-приложение вместо писем «охране → кэмпу → столовой». Заявитель один раз создаёт заявку,
диспетчер назначает машину тем, кому нужен транспорт, а охрана (КПП) и кэмп/столовая видят каждый свой список.

| Роль | Что видит и делает |
|---|---|
| **Заявитель** | Создаёт и редактирует **свои** заявки (один человек или бригада, импорт из Excel), видит статусы |
| **Диспетчер транспорта** | Люди с галочкой «Нужен транспорт»: кому ещё не назначена машина на **привоз** и на **вывоз**, по дням. Отмечает галочками людей и вписывает марку, госномер, водителя — или сажает в уже назначенную машину |
| **Охрана (КПП)** | Список ожидаемых на сегодня, «не прибывшие», кто на территории; отметки «Прибыл» / «Убыл» в одно нажатие; поиск по ФИО, госномеру, ИИН |
| **Кэмп и столовая** | Одна роль, потому что кэмп ведёт один человек и он же докладывает на кухню. Раздел **«Кэмп»**: люди с галочкой «Проживание»: заезжают сегодня (и прошли ли КПП), выезжают, проживают, ближайшие дни; корпус/комната, «Заселён» / «Выселен». Раздел **«Столовая»**: люди с галочкой «Питание»: количество завтраков/обедов/ужинов по дням и список людей |
| **Администратор** | Всё перечисленное + пользователи и роли + журнал действий |

ИИН и номера документов видят только заявитель (в своих заявках), охрана и администратор.
Кэмп/столовая документов не видят. В журнал действий ИИН не записывается.

## 1. Установка на сервер (Docker)

Нужно: Linux-сервер (или Windows Server с Docker Desktop), установленные **Docker** и **Docker Compose**.
Приложение и база PostgreSQL запускаются двумя контейнерами. Для 50–200 человек в день хватит 2 ГБ ОЗУ и 2 ядер.

```bash
# 1. Скопировать папку проекта на сервер, перейти в неё
cd kbm-arrivals

# 2. Создать файл настроек и заполнить его
cp .env.example .env
nano .env
```

В `.env` обязательно поменять:

- `DJANGO_SECRET_KEY` — длинная случайная строка. Сгенерировать:
  `python3 -c "import secrets; print(secrets.token_urlsafe(50))"`
- `POSTGRES_PASSWORD` — пароль базы данных.
- `DJANGO_ALLOWED_HOSTS` — имя сервера и/или IP, по которым сотрудники будут открывать сайт
  (например `arrivals.kbm.local,10.0.0.15`).

```bash
# 3. Собрать и запустить
docker compose up -d --build

# 4. Проверить, что всё работает
docker compose ps
docker compose logs -f web
```

Сайт откроется по адресу `http://<сервер>:8000` (порт задаётся в `WEB_PORT`).
При каждом запуске контейнер сам применяет обновления структуры базы.

### Пробный запуск с тестовыми данными

Поставьте в `.env` `SEED_DEMO=1` и запустите. Будут созданы тестовые аккаунты и около 20 человек
в разных статусах: сегодня, завтра, не прибывший, просроченный выезд, проживающие в кэмпе и т.д.
Можно и вручную:

```bash
docker compose exec web python manage.py seed_demo          # создать
docker compose exec web python manage.py seed_demo --reset  # удалить ВСЕ заявки и журнал и создать заново
```

| Логин | Роль |
|---|---|
| `admin` | Администратор |
| `zayavitel`, `zayavitel2` | Заявители |
| `ohrana` (КПП-1), `ohrana2` (КПП-2) | Охрана |
| `kemp` | Кэмп и столовая |
| `dispetcher` | Диспетчер транспорта |

Пароль у всех: **`demo1234`**.

> ⚠️ На рабочем сервере тестовые данные не нужны: верните `SEED_DEMO=0`, а тестовые аккаунты
> отключите или удалите (раздел «Пользователи»).

## 2. Первый администратор

```bash
docker compose exec web python manage.py createsuperuser
```

Команда спросит логин, e-mail (можно оставить пустым) и пароль. Созданный пользователь сразу получает роль «Администратор».

## 3. Как добавить пользователей

1. Войти под администратором → меню **«Пользователи»** → **«+ Добавить»**.
2. Указать логин, ФИО, **роль** и пароль.
   - Для **охраны** выберите **КПП**, на котором работает аккаунт: в отметке «Прибыл» будет видно, через какой КПП прошёл человек.
     Список КПП: кнопка «Список КПП» на странице пользователей.
   - Кэмп и столовая — одна роль «Кэмп и столовая»: обычно хватает одного общего аккаунта службы.
   - Если у пользователя указан e-mail и стоит галочка «получать уведомления», он будет получать письма о новых, изменённых и отменённых заявках (см. раздел 6).
3. Передать логин и пароль сотруднику. Свой пароль каждый может сменить, нажав на своё имя в верхней строке.

Уволенного сотрудника не удаляйте: снимите галочку **«Активен»**. Тогда его действия останутся в журнале с его именем.

## 4. Как работать

**Заявка.** «Заявки» → «+ Новая заявка». Для бригады нажмите «Добавить человека»: новая карточка
заполнится организацией, датами и галочками предыдущей. Кнопка «Скопировать данные первого на всех»
переносит даты и галочки первой карточки на всех остальных. Галочки можно потом поменять у каждого отдельно.

- **Однодневный визит**: дата выезда = дата прибытия, «Проживание в кэмпе» отключается. Такой человек не попадает к кэмпу.
- **Питание**: после включения появляются «Завтрак / Обед / Ужин». Нужно отметить хотя бы один приём пищи.
- После отметки «Прибыл» заявитель может менять только дату выезда и галочки, но не ФИО, документ и дату прибытия.
- «Отменить визит» у человека или «Отменить заявку» отменяет только тех, кто ещё не прибыл.

**Импорт из Excel.** В форме заявки нажмите «Скачать шаблон», заполните его и загрузите файл.
Обязательна только колонка «ФИО». Даты и галочки, которых нет в файле, берутся из первой карточки.
Перед сохранением список можно проверить и поправить. Если Excel «съел» ведущий ноль ИИН, он восстанавливается автоматически.

**КПП.** Вкладки «Ожидаются», «На территории», «Убыли сегодня». Красным выделены те, кто
не прибыл в назначенный день, жёлтым — те, у кого прошла дата выезда. Отметка ставится одним нажатием.
Если ошиблись, нажмите «Отменить» в зелёной плашке сверху. Госномер можно набирать кириллицей и с пробелами.

**Транспорт (диспетчер).** Если в заявке у человека стоит галочка «Нужен транспорт», свою марку и госномер
заявитель не пишет — человек попадает к диспетчеру. Вкладка «Привоз»: люди без машины по датам прибытия;
отметьте галочками, кого везёт одна машина, впишите марку, госномер, водителя, время и место подачи
(например, «у главного входа в офис») и нажмите «Назначить машину».
Заявитель сразу видит на странице заявки, когда, где и какая машина подъедет, и телефон водителя;
если у него указан e-mail — получает письмо (и ещё одно, если диспетчер поменяет время, место или машину).
Если машина на этот день уже есть, выберите её в списке «Куда посадить». Вкладка «Вывоз» — то же по датам выезда:
обратно человека обычно забирает другая машина. Водитель привозит людей и в тот же день уезжает.
Если заявитель перенёс дату или снял галочку, назначенная машина снимается и человек снова «без машины».

**Машины на КПП.** Вкладка «Машины»: рейсы диспетчера на сегодня — госномер, водитель, кого привозит или забирает.
Кнопки «Машина въехала» / «Машина выехала» отмечают водителя с машиной; «Все пассажиры прибыли» отмечает
всех пассажиров машины на привоз одним нажатием. Поиск по госномеру находит и машину, и её пассажиров.
Пока диспетчер не назначил машину, человек виден на КПП с жёлтой пометкой «Транспорт ещё не назначен».

**Кэмп.** Перед «Заселён» можно вписать корпус и комнату. На вкладке «Ближайшие дни» можно заранее
распределить комнаты на 3, 7 или 14 дней вперёд.

**Столовая.** Таблица на неделю, по стрелкам листается на неделю назад или вперёд. По клику на день открывается список людей.
Люди учитываются в каждом дне с даты прибытия по дату выезда включительно. Если человек уехал раньше
(отметка «Убыл» на КПП), со следующего дня он не считается. «Не прибывшие» включены в количество и выделены отдельно.

**Отчёты.** Меню «Отчёты» → выберите период и отчёт: «Прибытие и убытие» (охрана), «Питание» и «Кэмп»
(кэмп и столовая). Администратору доступны все три. Каждая выгрузка записывается в журнал.

**Журнал** (администратор): все входы, неудачные попытки входа, создание и изменение заявок, отметки КПП и кэмпа, выгрузки.
Можно фильтровать по пользователю, действию и датам. У каждой заявки внизу есть её собственная история.

## 5. Обслуживание

```bash
# Резервная копия базы (рекомендуется ежедневно, например через cron)
docker compose exec -T db pg_dump -U kbm kbm | gzip > backup_$(date +%F).sql.gz

# Восстановление из копии
gunzip -c backup_2026-10-23.sql.gz | docker compose exec -T db psql -U kbm kbm

# Обновление приложения (после замены файлов проекта)
docker compose up -d --build

# Остановка
docker compose down        # данные базы сохраняются в томе pgdata
```

**Служебная админка Django** (`/django-admin/`) — запасной инструмент администратора: справочники КПП и организаций
(тип организации: своя или подрядчик), просмотр данных. Журнал там доступен только для чтения.

## 6. HTTPS (когда будет домен)

Пока сайт работает по HTTP во внутренней сети. HTTPS нужен, когда охрана будет открывать сайт с телефонов
через мобильный интернет. В комплекте уже есть прокси **Caddy**: он сам получает бесплатный сертификат
Let's Encrypt и продлевает его.

1. Купить домен (например `arrivals.kbm.kz`) и в DNS создать A-запись на **внешний** IP сервера.
2. Открыть на сервере и межсетевом экране порты **80 и 443** из интернета (80 нужен для выдачи сертификата).
3. В `.env`:
   ```
   DOMAIN=arrivals.kbm.kz
   DJANGO_HTTPS=1
   WEB_PORT=127.0.0.1:8000
   SITE_URL=https://arrivals.kbm.kz
   ```
   `WEB_PORT=127.0.0.1:8000` закрывает прямой доступ по HTTP: сайт будет доступен только через HTTPS.
4. Запустить с HTTPS:
   ```bash
   docker compose --profile https up -d --build
   ```
5. Проверить, что `https://arrivals.kbm.kz` открывается с замком.

Если в компании уже есть свой обратный прокси с сертификатом, Caddy не нужен: запускайте как обычно,
задайте `DOMAIN`, `DJANGO_HTTPS=1` и настройте прокси на передачу заголовков `X-Forwarded-Proto` и `X-Forwarded-For`.

> Сайт с персональными данными будет доступен из интернета, поэтому выдайте всем
> сложные пароли, отключите тестовые аккаунты и регулярно просматривайте в журнале «Неудачный вход».

## 7. Вход через AD/LDAP (запланировано)

Сейчас вход по логину и паролю, пользователей заводит администратор. Позже планируется вход
под доменной учётной записью и синхронизация пользователей с AD: создание и отключение аккаунтов,
ФИО, почта, роль по группе AD. Заготовка подключения есть в `config/settings.py` (переменные `LDAP_*`),
но она не проверена и пакет `django-auth-ldap` пока не установлен. Для этой работы понадобятся от ИТ: адрес контроллера домена,
сервисная учётная запись для чтения, OU с пользователями и группы AD для каждой роли.

## 8. Почтовые уведомления (необязательно)

Если заполнить `EMAIL_HOST` и остальные `EMAIL_*` в `.env`, службы будут получать письма о новых, изменённых и отменённых заявках:
охрана — обо всех, диспетчер — если кому-то нужен транспорт, кэмп и столовая — одно письмо, если в заявке есть проживание или питание (в письме только эти люди).
ИИН в письма не попадает. Без `EMAIL_HOST` письма не отправляются, их текст только пишется в лог контейнера.

## 9. Казахский язык

Интерфейс сделан с поддержкой перевода (Django i18n), казахский язык уже указан в настройках. Чтобы добавить перевод:

```bash
python manage.py makemessages -l kk      # создаст locale/kk/LC_MESSAGES/django.po
# перевести строки в django.po (например, в программе Poedit)
python manage.py compilemessages
```

После этого язык переключается через `/i18n/setlang/` (стандартный механизм Django). Кнопку переключения
в шапке можно добавить, когда перевод будет готов.

## Для разработчиков

Стек: **Python 3.12, Django 5.2, PostgreSQL 16** (локально SQLite), шаблоны на сервере
без отдельного фронтенд-фреймворка (немного чистого JS только в форме заявки), openpyxl для Excel, gunicorn + whitenoise.

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_demo
.venv/bin/python manage.py runserver      # http://127.0.0.1:8000
.venv/bin/python manage.py test           # автотесты
```

Структура:

```
accounts/   пользователи, роли, КПП, вход
visits/     заявки и люди (models.py), отметки (services.py), формы, Excel (excel.py),
            экраны по ролям (views/: requests, kpp, camp, canteen, reports), seed_demo
audit/      журнал действий
templates/  HTML-шаблоны;  static/  CSS и JS
```

Модель данных: **Request** (заявка: цель, ответственный, комментарий, автор) → **Visitor**
(человек: ФИО, документ, организация, даты, транспорт, галочки кэмпа и питания, статус КПП
«Ожидается → Прибыл → Убыл / Отменён» с временем и тем, кто отметил, статус кэмпа
«Ожидает заселения → Заселён → Выселен», корпус и комната). **Trip** — рейс диспетчера (привоз или вывоз:
дата, машина, водитель, отметки въезда/выезда на КПП); у человека `arrival_trip` и `departure_trip`. Все смены статусов проходят через
`visits/services.py` и записываются в **AuditLog**.
