# Учёт прибытия на месторождение — АО «Каражанбасмунай»

Веб-приложение вместо писем «охране → кэмпу → столовой». Заявка проходит по цепочке:

**заявитель создаёт заявку → начальник штаба безопасности согласует → диспетчер назначает машину
(если нужен транспорт) → только после этого человека видят КПП и кэмп/столовая.**

Подрядчики и гости регистрируются сами с телефона (страница «Регистрация» на экране входа).

| Роль | Что видит и делает |
|---|---|
| **Заявитель** | Создаёт и редактирует **свои** заявки (один человек или бригада, импорт из Excel, завоз груза), видит статусы. Подрядчики регистрируются сами, логин — номер телефона |
| **Начальник штаба безопасности** | **«Обстановка»**: кто и какие машины сейчас на территории (по организациям), ожидаемые, не прибывшие, просрочен выезд, груз, лента отметок КПП, совпадения с запретом въезда; обновляется каждую минуту. **«Согласование»**: «Согласовать» (можно снять отдельных людей), «Отклонить» или позже «Отозвать согласование» с причиной. **«Проверка»**: все визиты человека/машины по ФИО, ИИН, госномеру. **«Запрет въезда»**: чёрный список по ИИН/документу и госномеру. Отчёт «Прибытие и убытие». Заявки не правит |
| **Диспетчер транспорта** | Люди с галочкой «Нужен транспорт»: кому ещё не назначена машина на **привоз** и на **вывоз**, по дням. Отмечает галочками людей и вписывает марку, госномер, водителя — или сажает в уже назначенную машину |
| **Охрана (КПП)** | Список ожидаемых на сегодня, «не прибывшие», кто на территории; отметки «Прибыл» / «Убыл» в одно нажатие; поиск по ФИО, госномеру, ИИН |
| **Кэмп и столовая** | Одна роль, потому что кэмп ведёт один человек и он же докладывает на кухню. Раздел **«Кэмп»**: люди с галочкой «Проживание»: заезжают сегодня (и прошли ли КПП), выезжают, проживают, ближайшие дни; корпус/комната, «Заселён» / «Выселен». Раздел **«Столовая»**: люди с галочкой «Питание»: количество завтраков/обедов/ужинов по дням и список людей |
| **Администратор** | Всё перечисленное + пользователи и роли + журнал действий |

ИИН и номера документов видят только заявитель (в своих заявках), начальник штаба, охрана и администратор.
Кэмп/столовая документов не видят. В журнал действий ИИН не записывается.

## 1. Установка на сервер (Docker)

Нужно: Linux-сервер (или Windows Server с Docker Desktop), установленные **Docker** и **Docker Compose**.
Приложение и база PostgreSQL запускаются двумя контейнерами. Для 50–200 человек в день хватит 2 ГБ ОЗУ и 2 ядер.

```bash
# 1. Скопировать папку проекта на сервер, перейти в неё
cd kbm-arrivals

# 2. Создать файл настроек и заполнить его
cp .env.example .env
nano .env
```

В `.env` обязательно поменять:

- `DJANGO_SECRET_KEY` — длинная случайная строка. Сгенерировать:
  `python3 -c "import secrets; print(secrets.token_urlsafe(50))"`
- `POSTGRES_PASSWORD` — пароль базы данных.
- `DJANGO_ALLOWED_HOSTS` — имя сервера и/или IP, по которым сотрудники будут открывать сайт
  (например `arrivals.kbm.local,10.0.0.15`).

```bash
# 3. Собрать и запустить
docker compose up -d --build

# 4. Проверить, что всё работает
docker compose ps
docker compose logs -f web
```

Сайт откроется по адресу `http://<сервер>:8000` (порт задаётся в `WEB_PORT`).
При каждом запуске контейнер сам применяет обновления структуры базы.

### Пробный запуск с тестовыми данными

Поставьте в `.env` `SEED_DEMO=1` и запустите. Будут созданы тестовые аккаунты и около 20 человек
в разных статусах: сегодня, завтра, не прибывший, просроченный выезд, проживающие в кэмпе и т.д.
Можно и вручную:

```bash
docker compose exec web python manage.py seed_demo          # создать
docker compose exec web python manage.py seed_demo --reset  # удалить ВСЕ заявки и журнал и создать заново
```

| Логин | Роль |

| `zayavitel`, `zayavitel2` | Заявители |
| `ohrana` (КПП-1), `ohrana2` (КПП-2) | Охрана |
| `nachalnik` | Начальник штаба безопасности |

Пароль у всех: **`demo1234`**.

## 2. Первый администратор

```bash
docker compose exec web python manage.py createsuperuser
```

Команда спросит логин, e-mail (можно оставить пустым) и пароль. Созданный пользователь сразу получает роль «Администратор».

## 3. Как добавить пользователей

Войти под администратором → **«Пользователи»** → **«+ Добавить»**.

- **Сотрудник КБМ (есть в домене):** отметить **«Сотрудник КБМ — вход паролем Windows»**, логин — доменный
  (`N_Ivanov`, можно `KBM\N_Ivanov`), выбрать роль. Пароль не задаётся. ФИО, почта и телефон подтянутся из AD при первом
  входе, выбранная роль сохранится. Обычным заявителям заводить ничего не нужно — они просто входят паролем Windows.
- **Подрядчик или гость:** логин — номер мобильного телефона (в любом виде, сохранится как `77011234567`),
  ФИО, организация, пароль. Пароль передайте человеку лично или по телефону; входить можно, набрав номер в любом формате.
- **Охрана:** выберите **КПП**, на котором работает аккаунт.
- **Роли** (начальник штаба безопасности, охрана, диспетчер, кэмп и столовая, администратор) меняются в карточке
  пользователя. Если в `.env` заданы группы `AD_GROUP_*`, роли сотрудников домена берутся из групп AD и ручная роль
  заменится при следующем входе.
- Уволенного не удаляйте: снимите **«Активен»** (сотрудник домена отключается и сам, когда его отключат в AD).
  У учётных записей домена пароль на сайте не меняется — только в Windows.

## 4. Как работать

**Согласование.** Новая заявка уходит начальнику штаба безопасности (ему же письмо, если указан e-mail).
До согласования её не видят диспетчер, КПП и кэмп, и отметить «Прибыл» нельзя. Начальник открывает заявку,
проверяет людей и груз, снимает галочку у тех, кого нельзя допускать (они получают статус «Не согласован»),
и нажимает «Согласовать». Или «Отклонить» с причиной: заявитель видит причину, исправляет заявку и сохраняет,
и она снова уходит на согласование. Изменения уже согласованной заявки повторно не согласуются.
Человека с галочкой «Нужен транспорт» КПП и кэмп увидят, только когда диспетчер назначит машину на привоз.

**Запрет въезда.** Начальник штаба добавляет человека (ИИН/номер документа) или машину (госномер) с причиной —
вручную или кнопкой «Запретить въезд» из заявки и из «Проверки». При согласовании такой человек подсвечен красным
и не отмечен к допуску (начальник может отметить его сознательно), в списке согласования у заявки метка «запрет въезда»,
на КПП у карточки красная строка и подтверждение перед «Прибыл». Заявитель запрет не видит. Снятые запреты остаются в истории.

**Отзыв согласования.** В согласованной заявке начальник может нажать «Отозвать согласование» с причиной: ещё не прибывшие
пропадают с КПП, у кэмпа и диспетчера и снимаются с машин, а кто уже на территории — остаётся у охраны, чтобы отметить убытие.
Заявитель получает причину и может исправить и снова отправить заявку.

**Доступ для подрядчиков и гостей.** Самостоятельная регистрация выключена (`SIGNUP_ENABLED=0`). На странице входа
написано: «Нет доступа? Если вас нет в домене kbm.kz или вы подрядчик — напишите на почту» (адрес — `ACCESS_EMAIL`,
по умолчанию N_Otegenov@kbm.kz); кнопка открывает письмо с шаблоном (ФИО, организация, телефон, для чего доступ).
Администратор заводит человека в «Пользователях» (см. раздел 3). Включить регистрацию обратно: `SIGNUP_ENABLED=1`.

**Завоз груза.** В заявке галочка «Завоз материалов или оборудования»: номер договора (обязательно), что везут,
дата, машина, водитель и документы (договор, накладная, сертификаты: PDF, фото, Word, Excel, до 10 МБ, до 10 файлов).
После согласования машина появляется на КПП во вкладке «Машины» с грузом, договором и документами; охрана отмечает въезд и выезд.
Документы открывают только автор заявки, начальник штаба, администратор и охрана (по согласованной заявке);
по прямой ссылке без входа их не скачать. Хранятся в томе Docker `media`.

**Заявка на машину** («Машина» → «+ Заказать машину»): откуда и куда (Офис Актау, БМТС (склад), Месторождение или
любой адрес), дата и время, кто едет (по одному в строке), груз, «нужна машина и обратно».
По городу (офис ↔ БМТС и т.п.) заявка сразу уходит диспетчеру. На месторождение — сначала начальнику штаба безопасности
(«Согласование» → «Поездки на месторождение»); для каждого пассажира нужен ИИН через запятую после ФИО.
Диспетчер на вкладке **«Поездки»** отмечает заявки одной даты и вписывает машину — можно посадить несколько заявок в одну
машину; там же «Выполнена», «Снять с машины», «Нет машины — отказать» (с причиной). Машину, которая едет на
месторождение или забирает оттуда, видит КПП во вкладке «Машины» вместе с пассажирами (с ИИН) и грузом.
Точки маршрута (название, адрес подачи, «охраняемая территория») правятся в служебной админке `/django-admin/`.

**Заявка.** «Заявки» → «+ Новая заявка». Для бригады нажмите «Добавить человека»: новая карточка
заполнится организацией, датами и галочками предыдущей. Кнопка «Скопировать данные первого на всех»
переносит даты и галочки первой карточки на всех остальных. Галочки можно потом поменять у каждого отдельно.

- **Однодневный визит**: дата выезда = дата прибытия, «Проживание в кэмпе» отключается. Такой человек не попадает к кэмпу.
- **Питание**: после включения появляются «Завтрак / Обед / Ужин». Нужно отметить хотя бы один приём пищи.
- После отметки «Прибыл» заявитель может менять только дату выезда и галочки, но не ФИО, документ и дату прибытия.
- «Отменить визит» у человека или «Отменить заявку» отменяет только тех, кто ещё не прибыл.

**Импорт из Excel.** В форме заявки нажмите «Скачать шаблон», заполните его и загрузите файл.
Обязательна только колонка «ФИО». Даты и галочки, которых нет в файле, берутся из первой карточки.
Перед сохранением список можно проверить и поправить. Если Excel «съел» ведущий ноль ИИН, он восстанавливается автоматически.

**КПП.** Вкладки «Ожидаются», «На территории», «Убыли сегодня». Красным выделены те, кто
не прибыл в назначенный день, жёлтым — те, у кого прошла дата выезда. Отметка ставится одним нажатием.
Если ошиблись, нажмите «Отменить» в зелёной плашке сверху. Госномер можно набирать кириллицей и с пробелами.

**Транспорт (диспетчер).** Если в заявке у человека стоит галочка «Нужен транспорт», свою марку и госномер
заявитель не пишет — человек попадает к диспетчеру. Вкладка «Привоз»: люди без машины по датам прибытия;
отметьте галочками, кого везёт одна машина, впишите марку, госномер, водителя, время и место подачи
(например, «у главного входа в офис») и нажмите «Назначить машину».
Заявитель сразу видит на странице заявки, когда, где и какая машина подъедет, и телефон водителя;
если у него указан e-mail — получает письмо (и ещё одно, если диспетчер поменяет время, место или машину).
Если машина на этот день уже есть, выберите её в списке «Куда посадить». Вкладка «Вывоз» — то же по датам выезда:
обратно человека обычно забирает другая машина. Водитель привозит людей и в тот же день уезжает.
Если заявитель перенёс дату или снял галочку, назначенная машина снимается и человек снова «без машины».

**Машины на КПП.** Вкладка «Машины»: рейсы диспетчера на сегодня — госномер, водитель, кого привозит или забирает.
Кнопки «Машина въехала» / «Машина выехала» отмечают водителя с машиной; «Все пассажиры прибыли» отмечает
всех пассажиров машины на привоз одним нажатием. Поиск по госномеру находит и машину, и её пассажиров.
Пока диспетчер не назначил машину, человек виден на КПП с жёлтой пометкой «Транспорт ещё не назначен».

**Кэмп.** Перед «Заселён» можно вписать корпус и комнату. На вкладке «Ближайшие дни» можно заранее
распределить комнаты на 3, 7 или 14 дней вперёд.

**Столовая.** Таблица на неделю, по стрелкам листается на неделю назад или вперёд. По клику на день открывается список людей.
Люди учитываются в каждом дне с даты прибытия по дату выезда включительно. Если человек уехал раньше
(отметка «Убыл» на КПП), со следующего дня он не считается. «Не прибывшие» включены в количество и выделены отдельно.

**Отчёты.** Меню «Отчёты» → выберите период и отчёт: «Прибытие и убытие» (охрана), «Питание» и «Кэмп»
(кэмп и столовая). Администратору доступны все три. Каждая выгрузка записывается в журнал.

**Журнал** (администратор): все входы, неудачные попытки входа, создание и изменение заявок, отметки КПП и кэмпа, выгрузки.
Можно фильтровать по пользователю, действию и датам. У каждой заявки внизу есть её собственная история.

## 5. Обслуживание

```bash
# Резервная копия базы (рекомендуется ежедневно, например через cron)
docker compose exec -T db pg_dump -U kbm kbm | gzip > backup_$(date +%F).sql.gz

# Документы на груз (том media)
docker compose run --rm -v "$PWD":/backup web tar czf /backup/media_$(date +%F).tar.gz -C /app media

# Восстановление из копии
gunzip -c backup_2026-10-23.sql.gz | docker compose exec -T db psql -U kbm kbm

# Обновление приложения (после замены файлов проекта)
docker compose up -d --build

# Остановка
docker compose down        # данные базы сохраняются в томе pgdata
```

**Служебная админка Django** (`/django-admin/`) — запасной инструмент администратора: справочники КПП и организаций
(тип организации: своя или подрядчик), просмотр данных. Журнал там доступен только для чтения.

## 6. HTTPS (когда будет домен)

Пока сайт работает по HTTP во внутренней сети. HTTPS нужен, когда охрана будет открывать сайт с телефонов
через мобильный интернет. В комплекте уже есть прокси **Caddy**: он сам получает бесплатный сертификат
Let's Encrypt и продлевает его.

1. Купить домен (например `arrivals.kbm.kz`) и в DNS создать A-запись на **внешний** IP сервера.
2. Открыть на сервере и межсетевом экране порты **80 и 443** из интернета (80 нужен для выдачи сертификата).
3. В `.env`:
   ```
   DOMAIN=arrivals.kbm.kz
   DJANGO_HTTPS=1
   WEB_PORT=127.0.0.1:8000
   SITE_URL=https://arrivals.kbm.kz
   ```
   `WEB_PORT=127.0.0.1:8000` закрывает прямой доступ по HTTP: сайт будет доступен только через HTTPS.
4. Запустить с HTTPS:
   ```bash
   docker compose --profile https up -d --build
   ```
5. Проверить, что `https://arrivals.kbm.kz` открывается с замком.

Если в компании уже есть свой обратный прокси с сертификатом, Caddy не нужен: запускайте как обычно,
задайте `DOMAIN`, `DJANGO_HTTPS=1` и настройте прокси на передачу заголовков `X-Forwarded-Proto` и `X-Forwarded-For`.

> Сайт с персональными данными будет доступен из интернета, поэтому выдайте всем
> сложные пароли, отключите тестовые аккаунты и регулярно просматривайте в журнале «Неудачный вход».

## 7. Вход через AD (доменная учётная запись)

Сотрудники КБМ входят под логином и паролем Windows (`N_Otegenov`, `KBM\N_Otegenov` или `N_Otegenov@KBM.KZ`).
Пароль проверяет контроллер домена, на сайте он не хранится. ФИО, почта и телефон берутся из AD при каждом входе.
Подрядчики (регистрация с телефона) и служебные локальные аккаунты входят как раньше; AD их не трогает.

**Роль** — по группе AD: кого ИТ добавил в группу (например `KBM-Propusk-Chief`), тот получает роль; убрали —
при следующем входе или синхронизации роль меняется. Без группы — `AD_DEFAULT_ROLE` (по умолчанию «Заявитель»:
любой сотрудник может подать заявку на гостя). `AD_DEFAULT_ROLE=` пусто — без группы на сайт не пускать.
КПП для охранника по-прежнему выбирает администратор в «Пользователях».

Настройка в `.env` (значения для КБМ):
```
AD_HOST=AOS22-DC02.KBM.KZ          # несколько контроллеров — через запятую
AD_DOMAIN=KBM.KZ
AD_BASE_DN=OU=KBM JSC,DC=KBM,DC=KZ
AD_SECURITY=ldaps                  # ldaps (636) или starttls (389); plain — только если ИТ разрешит
AD_GROUP_CHIEF=KBM-Propusk-Chief   # и остальные AD_GROUP_* — названия групп от ИТ
```
`plain` передаёт пароль по сети открытым текстом — используйте `ldaps`/`starttls` (нужен сертификат на контроллере
домена; у ИТ он обычно есть). `AD_CA_CERT` — путь к корневому сертификату домена, тогда сертификат DC проверяется.

**Проверка** (ничего не сохраняет): `python manage.py ad_check` — покажет, какие режимы шифрования доступны,
спросит ваш доменный логин и пароль и выведет, что сайт возьмёт из AD и какая будет роль.

**Синхронизация** (нужна служебная учётка только для чтения `AD_BIND_USER` / `AD_BIND_PASSWORD`):
`python manage.py ad_sync --dry-run` — посмотреть, `python manage.py ad_sync` — применить. Заводит участников групп
ролей заранее, обновляет данные, отключает тех, кого отключили или удалили в AD. Запускать по расписанию (раз в час):
на сервере — cron: `0 * * * * cd /путь/kbm-arrivals && docker compose exec -T web python manage.py ad_sync`.

Что попросить у ИТ: (1) LDAPS на контроллере домена (порт 636) или StartTLS; (2) доступ с сервера сайта к контроллеру
по 636/389; (3) группы ролей; (4) служебную учётку только для чтения для синхронизации.

## 8. Почтовые уведомления (необязательно)

Если заполнить `EMAIL_HOST` и остальные `EMAIL_*` в `.env`, службы будут получать письма о новых, изменённых и отменённых заявках:
охрана — обо всех, диспетчер — если кому-то нужен транспорт, кэмп и столовая — одно письмо, если в заявке есть проживание или питание (в письме только эти люди).
ИИН в письма не попадает. Без `EMAIL_HOST` письма не отправляются, их текст только пишется в лог контейнера.

**Подключение внутренней почты (Exchange).** Попросите у ИТ:

1. **Адрес SMTP-сервера** (например `mail.kbm.local` или IP Exchange) и порт.
2. **Как отправлять:** (а) *внутренний relay* — сервер приложения пускают отправлять без пароля, обычно порт 25
   (ИТ разрешает relay для IP сервера), или (б) *служебный ящик* `arrivals@…` с паролем, порт 587 с STARTTLS.
3. **Адрес отправителя** — от чьего имени уходят письма (`DEFAULT_FROM_EMAIL`).
4. **Можно ли отправлять наружу** (на gmail/mail.ru подрядчиков). Часто relay пускает только на внутренние адреса —
   тогда подрядчики уведомления не получат и смотрят статус заявки на сайте.

Вариант (а):
```
EMAIL_HOST=mail.kbm.local
EMAIL_PORT=25
DEFAULT_FROM_EMAIL=arrivals@kbm.kz
SITE_URL=http://адрес-сайта:8000
```
Вариант (б): то же плюс `EMAIL_PORT=587`, `EMAIL_USE_TLS=1`, `EMAIL_HOST_USER=arrivals@kbm.kz`, `EMAIL_HOST_PASSWORD=…`.

`SITE_URL` — адрес сайта, по нему строятся ссылки «Открыть» в письмах. Проверка после настройки:
```bash
python manage.py sendtestemail ваш.адрес@kbm.kz          # локально
docker compose exec web python manage.py sendtestemail ваш.адрес@kbm.kz   # на сервере
```
Пришло письмо — почта работает. Ошибка `Connection refused` / `timed out` — неверный адрес или порт закрыт;
`Relaying denied` — ИТ не разрешил relay для этого компьютера; `Authentication` — неверный логин/пароль.
Потом каждому сотруднику служб: «Пользователи» → указать e-mail и оставить галочку «получать уведомления».

## 8а. Уведомления в Telegram (выключено)

Сейчас выключено: в корпоративной сети Telegram запрещён. Пока в `.env` нет `TELEGRAM_BOT_TOKEN`, кнопок Telegram
на сайте нет, а контейнер `bot` не запускается (он в профиле `telegram`). Чтобы включить в будущем:
заполнить `TELEGRAM_*` и запустить `docker compose --profile telegram up -d`.

Начальнику штаба приходит «Новая заявка на согласование», диспетчеру — «Назначьте машину»,
заявителю — решение по заявке и данные машины (марка, госномер, водитель, телефон, время и место подачи),
охране и кэмпу — согласованные заявки. Почта и Telegram работают вместе: кто что подключил, туда и приходит.

1. В Telegram откройте **@BotFather** → `/newbot` → название (например «КБМ Пропуск») →
   имя бота на `bot` (например `kbm_propusk_bot`). BotFather пришлёт **токен** вида `123456789:AA...`.
2. В `.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456789:AA...
   TELEGRAM_BOT_USERNAME=kbm_propusk_bot
   ```
3. `docker compose up -d --build` — запустится контейнер `bot` (локально: `python manage.py telegram_bot`
   в отдельном терминале). Серверу нужен только выход в интернет к `api.telegram.org`, домен не нужен.
4. Каждый пользователь: нажать на своё имя вверху → **«Подключить Telegram»** → в Telegram **«Start»**.
   Отключить — там же или командой `/stop` боту.

Токен — это пароль от бота: не публикуйте его. Если он утёк, в @BotFather: `/revoke`.

## 9. Казахский язык

Интерфейс сделан с поддержкой перевода (Django i18n), казахский язык уже указан в настройках. Чтобы добавить перевод:

```bash
python manage.py makemessages -l kk      # создаст locale/kk/LC_MESSAGES/django.po
# перевести строки в django.po (например, в программе Poedit)
python manage.py compilemessages
```

После этого язык переключается через `/i18n/setlang/` (стандартный механизм Django). Кнопку переключения
в шапке можно добавить, когда перевод будет готов.

## Для разработчиков

Стек: **Python 3.12, Django 5.2, PostgreSQL 16** (локально SQLite), шаблоны на сервере
без отдельного фронтенд-фреймворка (немного чистого JS только в форме заявки), openpyxl для Excel, gunicorn + whitenoise.

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_demo
.venv/bin/python manage.py runserver      # http://127.0.0.1:8000
.venv/bin/python manage.py test           # автотесты
```

Структура:

```
accounts/   пользователи, роли, КПП, вход
visits/     заявки и люди (models.py), отметки (services.py), формы, Excel (excel.py),
            экраны по ролям (views/: requests, kpp, camp, canteen, reports), seed_demo
audit/      журнал действий
templates/  HTML-шаблоны;  static/  CSS и JS
```

Модель данных: **Request** (заявка: цель, ответственный, комментарий, автор) → **Visitor**
(человек: ФИО, документ, организация, даты, транспорт, галочки кэмпа и питания, статус КПП
«Ожидается → Прибыл → Убыл / Отменён» с временем и тем, кто отметил, статус кэмпа
«Ожидает заселения → Заселён → Выселен», корпус и комната). **Trip** — рейс диспетчера (привоз или вывоз:
дата, машина, водитель, отметки въезда/выезда на КПП); у человека `arrival_trip` и `departure_trip`. Все смены статусов проходят через
`visits/services.py` и записываются в **AuditLog**.
